# NovusAI — Cardiovascular Disease Risk Screening System

An AI-assisted clinical screening web application that helps doctors and healthcare staff assess patient cardiovascular risk in minutes. NovusAI combines **Supervised Machine Learning (XGBoost)**, **Deep Neural Networks (PyTorch MLP)**, **Unsupervised Population Clustering (K-Means & GMM)**, **Explainable AI (SHAP)**, and **Large Language Models (Groq / Mistral via LangChain)** to deliver clear, accurate, and non-alarming diagnostic insights.

**Course:** AI/ML Capstone Project — Parul University & TelcoLearn, 2027 Batch  
**Domain:** Healthcare  
**Dataset:** [Cardiovascular Disease Dataset (Kaggle)](https://www.kaggle.com/datasets/sulianova/cardiovascular-disease-dataset) — 70,000 patient records, 11 clinical features  

---

## 1. Problem Statement

Primary healthcare workers in rural or resource-constrained clinics often lack immediate access to cardiology specialists. NovusAI provides an intuitive, web-based tool that accepts standard clinical measurements (age, blood pressure, cholesterol, BMI, smoking status) and outputs:
- An official cardiovascular disease risk percentage and risk tier (**Low**, **Moderate**, or **High Risk**).
- Explainable feature driver breakdowns isolating why risk is elevated (via SHAP TreeExplainer).
- Neural comparative cross-verification (via a 4-layer PyTorch MLP).
- Population similarity cohort benchmarking (via K-Means & Gaussian Mixture Models).
- Empathetic, plain-language patient summaries generated by LLMs without alarming jargon.

## 3. End-to-End System Flow Chart

Below is the architectural flow chart demonstrating data flow through the NovusAI pipeline:

![NovusAI End-to-End System Flowchart](flowchart.png)

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│                             PRIMARY MODEL (Source of Truth)                       │
│  XGBoost Classifier (best_model.pkl) | Decision Threshold: 0.45 | Recall Optimized  │
│  Outputs: Official risk_score, prediction, risk_level & SHAP TreeExplainer drivers│
└───────────────────────────────┬──────────────────────────────────────────────────┘
                                │
     ┌──────────────────────────┼──────────────────────────┐
     ▼                          ▼                          ▼
┌─────────────────────────┐┌─────────────────────────┐┌─────────────────────────┐
│     SECONDARY MODEL     ││   UNSUPERVISED MODELS   ││        LLM LAYER        │
│PyTorch MLP (mlp_best.pt)││ K-Means & GMM Models    ││Groq API (compound-mini) │
│4-Layer Neural Network   ││Hard Cohort Clustering & ││Mistral API (Fallback)   │
│Comparative Evaluation   ││GMM Soft Probabilities   ││Plain Language Summaries │
└─────────────────────────┘└─────────────────────────┘└─────────────────────────┘
```

**Workflow Summary:**
1. The patient intake form submits data to the unified backend orchestrator (`POST /api/screen`).
2. **Primary Supervised Model (XGBoost)** processes the feature payload using a recall-optimized **0.45 decision threshold** as the **Single Source of Truth** for official diagnosis and risk tiering.
3. Real-time **SHAP TreeExplainer** calculates primary risk drivers and protective factors.
4. **Secondary Model (PyTorch MLP)** provides independent deep-learning comparative evaluation without polluting primary decision provenance.
5. **Unsupervised Pipeline (K-Means & GMM)** assigns hard cohort categorizations and soft-clustering probability distributions.
6. **LangChain LLM Engine (Groq API primary ➔ Mistral API fallback)** translates metrics and SHAP values into an empathetic plain-language JSON summary for patients.
7. Record is saved to the SQLite database and rendered on the interactive React frontend.

## 7. Key API Reference

### `POST /api/screen` (Main Frontend Endpoint)
Accepts patient measurements, executes XGBoost, PyTorch MLP, K-Means/GMM, SHAP, and LLM translation, returning a unified `ScreeningReport`:

```json
{
  "final_risk_pct": 51.0,
  "risk_tier": "Moderate Risk",
  "population_comparison_tier": "Moderate Risk",
  "prediction": "Disease",
  "top_factors": [
    {"feature": "ap_hi", "label": "High Systolic Blood Pressure", "value": "+0.85", "impact": "high"},
    {"feature": "age", "label": "Older Age", "value": "+0.42", "impact": "moderate"}
  ],
  "patient_summary": "Your screening indicates moderate cardiovascular risk. While blood pressure is elevated, lifestyle modifications can significantly lower overall risk.",
  "key_factors": ["Elevated Systolic Blood Pressure", "Above Normal BMI"],
  "suggested_next_step": "Consult your primary healthcare provider for blood pressure management and lifestyle guidance.",
  "value_explanations": {
    "smoke": "Non-smoker",
    "active": "Physically active",
    "cholesterol": "Normal level",
    "gluc": "Normal level"
  },
  "clustering_confidence": {
    "Low Risk": 0.0008,
    "Moderate Risk": 0.0000,
    "High Risk": 0.9992
  },
  "screening_id": 14
}
```

### `POST /predict`
Returns raw predictions from XGBoost, PyTorch MLP, K-Means, and SHAP drivers for technical inspection.

### `GET /api/records` & `PATCH /api/records/{id}`
Doctor-only endpoints for listing historical patient records, editing intake values, filtering pending review queues, and confirming clinical diagnoses ("Disease" vs "No Disease").

### `POST /api/rollback-model`
Emergency endpoint to restore the previous model version (`best_model_previous.pkl`) in memory.

## 8. Running the Project Locally

### Prerequisites
- Python 3.10+
- Node.js 18+
- Groq API Key or Mistral API Key (set in `backend/.env`)

### Backend Setup
1. Navigate to backend:
   ```bash
   cd backend
   ```
2. Create and activate a virtual environment:
   ```bash
   python -m venv venv
   # On Windows:
   venv\Scripts\activate
   ```
3. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```
4. Create a `backend/.env` file with your keys:
   ```env
   GROQ_API_KEY=your_groq_api_key_here
   MISTRAL_API_KEY=your_mistral_api_key_here
   ```
5. Start the API server:
   ```bash
   uvicorn app.main:app --reload
   ```
   The backend API will run at `http://localhost:8000`.

### Frontend Setup
1. Open a new terminal and navigate to frontend:
   ```bash
   cd frontend
   ```
2. Install Node dependencies:
   ```bash
   npm install
   ```
3. Start the Vite dev server:
   ```bash
   npm run dev
   ```
   Access the frontend application at `http://localhost:5173`.
